- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})`
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})`（用語を1つずつ検索）
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})`
- 1つの質問での LLM 呼び出し回数（`requests`）：上の3つの質問はいずれも 2 回（ツールを呼ぶ判断で1回、結果を見て回答するので1回）。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)`。説明は「指定した回（1始まりの整数）の用語から確認問題を1問作り、問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」。用語がない回には、確認問題を作れないというメッセージを返す。`uv run pytest -q` は 21 件すべて成功した。

## 宿題

- 取り組んだレベル：発展（b）

- やったこと：Pi 1.5.0 をインストールし、`gemini-3.5-flash-lite` で動かした。公開リポジトリの `system-prompt.ts`（コミット `7d07332`）と、Pi が実際にモデルへ送ったシステムプロンプトを読み、`INSTRUCTIONS` と比べた。さらに同じ質問を Pi と自分のエージェントに投げて、ふるまいも比べた。
  - 実行方法は問題文の `pi` と `/model` ではなく、記録を残すために非対話モードにした。
  - Pi は確認なしで操作するので、読み取り系のツールだけを許可した。

    ```bash
    pi -p --mode json --model google/gemini-3.5-flash-lite --tools read,grep,find,ls --no-approve "質問" </dev/null
    ```

- 結果：

  プロンプトの比較

  | 観点 | Pi のシステムプロンプト | 自分の `INSTRUCTIONS` |
  |---|---|---|
  | 役割 | 汎用のコーディング支援（ファイルを調べる、コマンドを実行する、コードを直す） | AIE2026 の学習支援に限定 |
  | ツール | 有効なツールの一覧を実行時に組み立てて載せる。使い方の注意もツールごとに持つ（例：cat や sed ではなく read を使う） | ツール名を手で書く。説明は各ツールの docstring に任せる |
  | 手順 | 順序の指定はほぼない | 「答える前に必ず search_glossary で確認する」と指定 |
  | 情報がないとき | 書かれていない | 「推測で断定せず、用語集にはないと伝える」 |
  | 回答の形式 | 簡潔に書く、ファイルパスを明示する | 最後に関係する回（第N回）を示す |
  | 方針 | 書かれていない | 宿題の答えそのものは書かず、ヒントで導く |
  | 環境の情報 | 作業ディレクトリ、Pi 自身の文書の場所（聞かれたときだけ読む） | なし |
  | 拡張 | `AGENTS.md` / `CLAUDE.md`、スキル、追加の指示を差し込める | なし（固定の文字列） |
  | 構成 | `<tools>` `<rules>` などのセクションに分かれ、セクション単位で更新できる | 箇条書き5行 |

  ふるまいの比較

  | 質問 | Pi | 自分のエージェント |
  |---|---|---|
  | 「3レベル」とは？ | 4 requests。grep でリポジトリを探し、`data/glossary.json` と README を読んで正しく回答 | 2 requests。`search_glossary` 1回で正しく回答 |
  | LoRAとQLoRAの違いは？ | 1 request。ツールを使わず、NF4 や RTX 3090 などを含む一般知識で詳しく回答。出典や回の表示なし | 2 requests。用語を1つずつ検索し、用語集に沿って短く回答。最後に第2回と表示 |
  | 第3回の宿題の答えをそのまま教えて | 16 requests。リポジトリを読み回り、コードを含む解答例を書いた | 1 request。答えを断り、ヒントを返した |

  - 実行時の問題：標準入力を閉じないと、非対話モードの Pi は応答しなかった（`</dev/null` で解決）。無料枠の上限（15 リクエスト/分）にも当たり、429 エラーで止まったので、1 分以上空けて再実行した。上の表の Pi の結果のうち、1 行目と 3 行目は再実行の結果である。2 行目は最初の実行の結果で、`--offline` を付けていたが、ツールを使っていないので結果には影響しない。
  - 再実行でも `find` は `fd` を取得できず失敗した（`grep` は使えた）。Pi の request 数には、この失敗分も含まれる。

- 気づき・疑問：
  - Pi のプロンプトは「どんな作業にも使える道具の使い方」、`INSTRUCTIONS` は「この講座で何をしてよいか」を書いている。Pi に方針が少ないのは、プロジェクトごとの方針を `AGENTS.md` などで足す設計だからだと考えた。
  - 「宿題の答えを書かない」という1行の差が、回答の差として最もはっきり出た。この方針を持たない Pi は解答例を書き、その中で、実行していない実験の結果まで「結果と記録の書き方例」として書いた（`bash` を許可していないので実行できない）。「推測で断定しない」のような指示が書かれていない場合に起こりうることだと感じた。
  - 検索用のツールと「必ず使う」という指示があると、少ないリクエストで用語集に沿った回答になる。Pi は `grep` や `read` で自分で探すので、どのリポジトリでも使えるが、リクエストが増えやすく、無料枠の上限にも当たりやすい。LoRA の質問のように、リポジトリに情報があっても探さずに答える場合もあった。
  - ただし、指示が必ず守られるわけではない。自分のエージェントは「宿題の答えをそのまま教えて」に対して `search_glossary` も `get_lecture_summary` も呼ばず、第3回の内容に基づかない一般的なヒントを返した。また、LoRA の回答の末尾には `第2回</code>` という崩れた文字列が出た。
  - 疑問：`INSTRUCTIONS` に「宿題を聞かれたら get_lecture_summary を使う」と足せば、ヒントの質は上がるのか。また、Pi に `AGENTS.md` で同じ方針を与えると、宿題の質問への回答はどこまで変わるのか。
